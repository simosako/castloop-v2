# ワークスペースバックアップの設計

ワークスペースバックアップは、ローカルの管理ファイルを暗号化アーカイブに保存する機能です。作成、検証、復元プレビュー、復元の4コマンドで構成し、処理はローカルで完結します。操作方法は[バックアップ利用ガイド](../../docs/workspace_backup.md)を参照してください。

## 保存対象

サービス設定、管理者キー、Showの編集用ファイル、操作の進捗記録を保存します。R2やDO SQLiteのデータは、このバックアップの範囲外です。

| 対象 | 扱い |
| --- | --- |
| `castloop.toml`、存在する `castloop-admin.toml` | 保存。サービス設定を先頭エントリにする |
| `.castloop/secrets.json` | 管理者キーを保存 |
| [既知の記録ディレクトリ](../data/storage.md) | 配下の通常ファイルを再帰的に保存 |
| `show.toml` があるShowディレクトリ | 直下の通常ファイルを保存 |
| Show直下の `*.mp3` | `--include-audio` 指定時に保存 |
| ロック、一時ファイル、`.gitignore` | 除外理由を記録。保護用の `.gitignore` は復元時に生成 |
| 未知のトップレベル項目・記録種別、Showのサブディレクトリ | 除外して一覧に記録 |

走査対象のShow・記録ディレクトリ内にシンボリックリンクがあればエラーにします。除外項目は、結果とマニフェストの両方から確認できます。

バックアップ中は、ワークスペースの編集やCLIの変更操作を停止します。ファイルを順に読むため、読み取り中に内容が変わらない状態で実行します。

## 作成の流れ

1. 対象ファイルとサイズを列挙します。
2. 各ファイルを1回読み、SHA-256を計算しながら暗号化アーカイブへ書き込みます。
3. ファイル一覧と検査情報をまとめたマニフェストを末尾へ書き込みます。
4. アーカイブ末尾のハッシュを書き込みます。

出力先は新規ファイルとして作成し、失敗した不完全ファイルは除去します。未完了操作の要約にはドメイン変更の記録を使い、読み取れなかった記録は `scan_errors` に残します。

## アーカイブ形式

拡張子は `.clbk`、マジック文字列は `CASTLOOP-BACKUP-1` です。

```text
平文マジック + 改行
平文ヘッダーJSON + 改行
暗号化チャンク列
暗号化領域全体のSHA-256（32バイト）

復号後の内容：
  エントリヘッダー → ファイル本文 → ファイルSHA-256
  …
  マニフェストJSON
```

| 項目 | 形式 |
| --- | --- |
| 鍵導出 | scrypt、`N=32768`、`r=8`、`p=1`、salt 16バイト、鍵32バイト |
| 暗号 | AES-256-GCM。チャンクごとにnonce 12バイト、認証タグ16バイト |
| 作成時の平文チャンク | 4 MiB |
| フレーム | 種別1バイト、長さ8バイト（ビッグエンディアン）、本文 |
| ファイル検査 | 本文のSHA-256、マニフェストのパス・サイズ・件数を照合 |
| 末尾ハッシュ | 暗号化領域の転送破損・切断を検出 |

ヘッダーのサービスID、CLI版、日時、件数、鍵導出情報などは平文です。管理者キーとファイル本文は暗号化領域に入ります。形式のフィールドは[スキーマ](../data/schemas.md)を参照してください。

### パスフレーズ

UTF-8で8〜1024バイトとし、TTYの入力または専用ファイルから受け取ります。JSON・非対話実行ではファイルを指定します。誤ったパスフレーズと暗号データ破損は、同じ固定メッセージで報告します。

## 検証と復元

| 操作 | 処理 |
| --- | --- |
| `backup-verify` | 全体を復号し、暗号認証、エントリ、マニフェスト、末尾ハッシュを検査する。設定の妥当性は `config_valid` で返す |
| `backup-restore-preview` | 同じ検査を行い、展開予定と保存先の存在を返す |
| `backup-restore` | 新規ディレクトリへ展開し、整合性確認後にローカル保護設定を生成する |

復元では、絶対パス、親ディレクトリへの遡行、重複パスを拒否します。先頭の `castloop.toml` を検証してから、存在しない保存先を作ります。途中で失敗した場合は、この処理が作った部分展開先を除去します。

復元完了後は、管理者キーとローカル記録を使って管理を再開できます。未完了のリモート操作は、復元後に状態を確認し、利用者が実行を判断します。
