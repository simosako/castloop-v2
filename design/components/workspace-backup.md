# ワークスペースバックアップの設計

バックアップは、ローカルの管理ワークスペースを暗号化アーカイブへ保存し、整合性検査と別ディレクトリへの復元を行う。4コマンドともネットワークへ接続せず、Cloudflare API認証用の環境変数を読まない。

**R2やShow DO SQLiteは取得しない。** 公開内容・履歴・予約・統計を含むサービス全体のバックアップではない。

## 対象選別

| 対象 | 扱い |
| --- | --- |
| `castloop.toml`、存在する `castloop-admin.toml` | 保存。サービス設定を先頭エントリにする |
| `.castloop/secrets.json` | 管理者キーを保存 |
| [既知の6記録ディレクトリ](../data/storage.md) | 配下の通常ファイルを再帰的に保存 |
| `show.toml` を持つShowディレクトリ | 直下の通常ファイルを保存。サブディレクトリは除外 |
| Show直下の `*.mp3` | 既定では除外。`--include-audio` 指定時のみ保存 |
| ロック、一時ファイル、再生成する `.gitignore` | 理由を記録して除外 |
| 未知のトップレベル項目、未知の記録種別 | `unknown` として記録して除外 |

対象として走査するShow・記録ディレクトリ内のシンボリックリンクは拒否する。未知の項目を「すべて安全に保存できた」と扱わず、除外一覧を結果とマニフェストに残す。

バックアップ中はワークスペースを編集せず、他の変更操作も実行しない。個別記録の原子的な置換は、複数ファイル全体が同じ時点に属することを保証しない。

## 作成

最初に対象とサイズを列挙し、その後、各ファイルを1回読みながらSHA-256、エントリ、暗号化出力を生成する。マニフェスト（ファイル一覧と検査情報）はハッシュが確定した後の末尾に置く。出力先は新規ファイルとして作り、失敗した不完全アーカイブは除去する。

未完了操作の要約はドメイン変更だけを対象とする。記録を読み取れなかった場合は `scan_errors` に残す。通常公開の成否やリモート状態を推定するものではない。

## 暗号化と形式

拡張子は `.clbk`、マジックは `CASTLOOP-BACKUP-1`。構造は次のとおり。

```text
平文マジック + 改行
平文ヘッダーJSON + 改行
暗号化チャンク列
暗号化領域全体のSHA-256（32 bytes）

復号後：
  エントリヘッダー → ファイル本文 → ファイルSHA-256
  …
  マニフェストJSON
```

| 項目 | 値・役割 |
| --- | --- |
| 鍵導出 | scrypt、`N=32768`、`r=8`、`p=1`、salt 16 bytes、鍵32 bytes |
| 暗号 | AES-256-GCM、チャンクごとにnonce 12 bytesと認証タグ16 bytes |
| 作成時の平文チャンク | 4 MiB |
| フレーム | 種別1 byte、長さ8 bytes（ビッグエンディアン）、本文 |
| ファイル検査 | 各本文のSHA-256とマニフェストのパス・サイズ・件数等を照合 |
| 末尾ハッシュ | 転送破損・切断の検出。暗号認証の代わりにはしない |

ヘッダーにはサービスID、CLI版、日時、件数、KDF情報等が平文で入る。管理者キーとファイル内容は暗号化される。マニフェストのフィールドは[スキーマ](../data/schemas.md)を参照する。

パスフレーズはUTF-8で8〜1024 bytes。専用ファイルまたはTTYからだけ受け取り、引数や環境変数は使わない。JSON・非対話実行ではファイル指定が必要。誤パスフレーズと暗号データ破損は同じ固定メッセージで報告する。

## 検証と復元

| 操作 | 結果 |
| --- | --- |
| `backup-verify` | 全体を復号し、暗号認証・エントリ・マニフェスト・末尾ハッシュを検査。設定の妥当性は `config_valid` で別に返す |
| `backup-restore-preview` | 同じ検査を行い、展開予定と保存先の存在を報告。ファイルは作らない |
| `backup-restore` | 存在しない保存先だけに展開し、整合性確認後にローカル保護設定を再生成 |

絶対パス、親への遡行、重複パス等を拒否する。先頭の `castloop.toml` を検証するまで保存先を作らない。展開中に失敗した場合は、この処理で作った部分展開先を除去する。既存ワークスペースへマージ・上書きする処理はない。

復元は管理者キーとローカル記録を戻すだけで、未完了のドメイン変更や公開要求を実行しない。復元後のローカル検査と、必要なリモート操作の確認・承認は別である。
