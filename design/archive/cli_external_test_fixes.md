# 外部環境テストで判明したCLIの修正

## 2026-09-30: サブコマンドのヘルプ

外部環境でv0.1.1の`init --help`、`create-show --help`、`create-episode --help`が`Invalid or missing value for --help`になった。

- 原因: 引数解析が全`--`フラグに値を要求し、トップレベル以外の`--help`を特別扱いしていなかった。
- 修正: 全実装済みサブコマンドの`--help`/`-h`、`help COMMAND`を通常引数の解析前に処理する。構文、実行ディレクトリ、公開・stagingの違いを表示する。設定・認証情報なしでも表示可能で、Cloudflareへの接続やworkspace作成は行わない。
- 確認: 全サブコマンドのhelp、引数の後のhelp、短縮形、未知コマンドと通常オプションの値不足をCLI subprocessの自動テストで検証する。
- 結果: `npm run check`、`bun test`（27件）、`git diff --check`に合格。Linux x86-64バイナリを再ビルドし、報告された3コマンドの`--help`が正常終了して説明を表示することを確認した。
- 公開済みv0.1.1バイナリは変更しない。修正版の配布には新しいReleaseが必要。

## 2026-09-30: 初回initのhealth待機

外部ログでは初回`init`が6回のHTTP 404で失敗し、同じworkspaceからフラグなしで再実行した`init`は成功した。リソース作成自体の失敗は記録されていない。

- 原因: 旧実装は2秒間隔・6回固定であり、応答がすぐ404になる場合の待機は約10秒にとどまる。初回Worker URLの準備がこの枠を超えると失敗する。ログだけでCloudflare内部の遅延原因や反映時間は特定できない。
- 修正: 単調時計による120秒の期限を設け、404・429・5xx・通信失敗を5秒間隔で再試行する。通信時間も期限に含め、各通信は最大5秒（期限が近い場合は残り時間）で打ち切る。待機状況と残り時間をstderrへ表示する。401/403等は即時停止し、redirectは追従しない。
- 再開: provisioningの完了済み手順・管理鍵の保存処理は変更しない。時間切れでもworkspaceを残し、同じworkspaceでフラグなしの`init`を再実行する。Cloudflare作成成功後の応答喪失によるreconcileは別の既存残件であり、今回の修正対象外。
- 確認: 6回を超える404後の成功、通信失敗・503・429、恒久エラー、2分の上限、通信時間込みの期限、進捗表示を模擬時計とHTTP応答で検証する。実Cloudflare上での初回反映待ちは修正版バイナリでの再試験が必要。
- 結果: `npm run check`、`bun test`（32件）、`git diff --check`に合格。期限直前の通信が短縮されたAbortSignalで実際に中断されるテストにも合格。Linux x86-64バイナリの再ビルドに成功した。Cloudflare上のリソースは変更していない。
