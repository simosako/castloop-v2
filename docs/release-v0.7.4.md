# castloop v0.7.4

This release adds read-only observation commands for diagnostics, publication progress, external delivery verification and bounded terminal watching, separates Show admission from public delivery, adds an administrator timezone preference with offline schedule preview, extends native binary distribution to macOS (Apple Silicon) and Windows x64, and updates Zod to a patched version.

## Changes

- **Issue #67 — observation commands.** Four read-only CLI commands with machine-readable codes, scoped checks and `next_actions` for AI-agent operation: `diagnose` classifies local/remote/cross/external checks per explicitly listed Show (including one Cloudflare account read for token validity); `progress` merges local journals and remote status into a per-job phase view with FIFO waiting reasons; `verify` checks public Feed, cover and audio delivery through public-path GET/HEAD only, without an administrator key; `watch` observes one job until its terminal state with bounded budgets, stderr JSON events and exit codes 0/1/2 (SIGINT exits 130). None of them mutate, repair, resume, purge or replay anything, and `queued` is never reported as publication success. See the [observability guide](observability.md).
- **Issue #66 — admission and delivery separation.** Each Show has three availability states: `open`, `admission_paused` (new requests rejected, published delivery continues) and `paused` (both stopped). New commands `show-admission-pause`, `show-delivery-resume` and `show-control-status` join `show-pause`/`show-resume`. Requires fresh services with internal queue/content schemas **7/7** and the `availability_controls="show-admission-delivery-v1"` health capability; already-accepted jobs still run to completion after a pause. Existing services are not migrated. See the [archived availability guide](../design/archive/show_availability.md).
- **Issue #65 — administrator timezone.** An optional workspace `castloop-admin.toml` records an IANA timezone for display purposes only (service identity and stored timestamps are unchanged), and `preview-schedule-time` performs offline, ambiguous-DST-rejecting date/time conversion. See the [administrator configuration guide](admin_configuration.md).
- **Issue #73 — multi-platform binaries.** Releases distribute `castloop-macos-arm64` and `castloop-windows-x64.exe` alongside `castloop-linux-x64`, each built and smoke-checked natively on a matching GitHub-hosted runner and covered by the combined `SHA256SUMS`. The binaries remain unsigned; see the [distribution guide](cli_binary_distribution.md).
- **Issue #78 — dependency security update.** Zod is pinned to `^4.6.6` (resolved 4.6.7) for CVE-2023-54404/GHSA-mrhx-c7xc-m3w5. No castloop-specific exploitation was reported, and input limits, authentication, diagnostic allowlists and persisted formats are unchanged. See the [update record](zod_security_update_20261025.md).

## Verification and limitations

- Issue #67 was verified on a disposable native environment: `diagnose` 15 checks pass, a concurrent `watch` observed a publication from `running` to `succeeded` (exit 0), `verify` passed Feed GUID/origin/cover checks and an audio Content-Length match, and `diagnose --external` passed 16 checks. See the [verification record](../design/remote_diagnostics_live_verification_20261025.md). The environment was disposed after administrator approval with full local evidence retention. Fault paths (network partition, blocked jobs, missing jobs, interruption) are covered by the local regression suite, not by native fault injection; long waits beyond the default `watch` budget, CPU time and billing line counts are not measured.
- Issue #66's three-state controls require fresh 7/7 services; the v0.7.3 two-Show custom-domain trial does not validate them. No performance, full Free-plan compatibility or native fault-injection claims are made.
- Release and installation do not deploy, resume or modify any Cloudflare resource.
