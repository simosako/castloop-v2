# castloop v0.8.8

This release simplifies everyday CLI operation: management commands now find the workspace from parent directories, and a new `--review` mode confirms and publishes in one command on an interactive terminal. It also stops fresh control Durable Object instances from creating Show-only storage tables that the control path never uses. Service configuration and persisted formats are unchanged.

## Highlights

- Most management commands and `backup-create` now locate the nearest workspace by searching the current directory and up to five parent directories for `castloop.toml`. An explicit `--workspace` still selects only the specified directory, and an Episode run from inside a matching Show directory can omit both `--workspace` and `--show`. `init`, `doctor`, and `preview-schedule-time` keep their previous behavior, and commands that do not use a workspace do not search. See [running commands from other directories](https://github.com/simosako/castloop-v2/blob/v0.8.8/docs/getting_started.md#running-commands-from-other-directories).
- `publish-show` and `publish-episode` accept a new `--review` option for interactive terminals. It fetches the remote preview, shows the workspace, service, target, before/after differences, audio and cover details, and warnings, then asks for an explicit `publish` confirmation in the same process. After confirmation it re-reads the service configuration and re-validates the reviewed input and its remote update source before publishing, passing the reviewed fingerprint internally so the 64-digit hash no longer needs to be copied by hand. Refusing the prompt performs no upload and no publication. Combining `--review` with `--json` or `--non-interactive` is an error, and the existing `preview-*` plus `publish-* --expect-preview HASH` flow is unchanged. See the [publication guide](https://github.com/simosako/castloop-v2/blob/v0.8.8/docs/publishing.md).
- A fresh control DO now creates only the five tables its control path uses (service identity, format version, domain changes, show registry, domain connection) instead of also creating eleven Show content and schedule tables it never reads. Schedule table definitions moved to the Show-side schedules component, and health responses are shared between the control and Show compositions. Persisted SQLite formats and schema versions (14/13), DO class names, bindings, and the wire protocol are unchanged. Existing control DOs keep their previously created unused tables; no migration is performed. See the [control DO storage study](https://github.com/simosako/castloop-v2/blob/v0.8.8/design/control-do-storage-issue-109.md) for issue #109.
- Documentation: the getting-started and publication guides were restructured around running commands from the workspace and Show directories, README usage was clarified, and completed design studies were archived (CLI usability for issue #119, domain journal decision for issue #111, diagnostics granularity for issue #112, CLI management client for issue #110) together with the free-tier delivery scaling study and private trial environment records.

## Requirements and updates

Service configuration and supported internal formats are unchanged from v0.8.7. To get started, follow the [installation guide](https://github.com/simosako/castloop-v2/blob/v0.8.8/docs/installation.md) and the [first publication guide](https://github.com/simosako/castloop-v2/blob/v0.8.8/docs/getting_started.md). The guides are also available in [Japanese](https://github.com/simosako/castloop-v2/blob/v0.8.8/docs/README_ja.md).

To update an existing installation, follow the [CLI update instructions](https://github.com/simosako/castloop-v2/blob/v0.8.8/docs/installation.md#update-the-cli). Replacing the CLI binary is enough; no service-side update or data migration is involved. Commands that previously required `--workspace` keep working unchanged, and automation should continue to pass explicit `--workspace` / `--show` / `--expect-preview` as before.

## Verification

GitHub Actions runs type checking and the full local test suite on Linux and builds and smoke-tests the release binaries on Linux x64, macOS arm64, and Windows x64. The pull request CI run for this release completed successfully: the local test suite, the type check, and the three-platform build and smoke checks all passed. New tests cover parent-directory workspace discovery (explicit override, nested directories, invalid nearby configurations, and commands excluded from search) and the interactive review mode (confirmation, refusal, non-terminal use, `--json`/`--non-interactive` rejection, and re-validation after confirmation).

The workspace discovery and `--review` behavior was additionally exercised in an approved private live trial on 2026-11-02 against commit `79abc57`, including publication of a show and three episodes from an interactive terminal with automatic workspace and show detection. The control DO table reduction was exercised in a separate approved private live trial on 2026-11-02 against commit `b578f14` with the same change applied. Both environments were protected by Cloudflare Access, verified against anonymous access before and after publication, and disposed of after the trials. The records are kept under [design/archive](https://github.com/simosako/castloop-v2/blob/v0.8.8/design/archive/README.md). No live Cloudflare testing was performed for this release itself.
