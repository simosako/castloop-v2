# 利用ガイド

`docs/` は、castloopでPodcastを管理する人と、その操作を支援するエージェント向けのガイドです。導入・公開・日常運用の手順を説明します。内部の処理やデータ構造は[設計文書](../design/README.md)、ソースからの開発は[CONTRIBUTING.md](../CONTRIBUTING.md)を参照してください。

## 対象と用語

現行版は **v0.8.0** です。新規作成したサービス設定 `schema_version = 2`、`publication_protocol = "sqlite-sequential-v1"`、`storage_layout = "show-v1"`、内部queue/content形式 **14/13** を対象にします。Show・Episodeのメタデータは別の形式で、`schema_version = 1` を使います。

古いサービスの移行・既存資源の採用・内部形式の変換は提供しません。設定の版だけを書き換えて使わないでください。現在の対応条件と検証範囲は[v0.8.0リリースノート](release-v0.8.0.md)に記載しています。

| 用語 | 意味 |
| --- | --- |
| サービス | 一つのWorkerと非公開R2バケットで管理する単位。複数の番組を持てます |
| Show | 番組。専用のRSSと、番組ごとに分離した公開状態・履歴を持ちます |
| Episode | 番組内の各回。MP3音声とタイトル・説明・公開日時などを持ちます |
| ワークスペース | `castloop.toml`、秘密を含む `.castloop/`、番組別の編集ファイルを置く管理ディレクトリ |
| リビジョン | サーバーに保存した内容の版。過去版の確認・採用に使います |

## 操作に共通する注意

- CLIはCloudflare上の実資源と公開内容を変更します。対象・公開範囲・費用を確認し、エージェントには許可する操作を明示してください。文書の例や過去の承認は、新しい操作の許可ではありません。
- 作成・プレビューは公開しません。公開は `publish-*`、予約は `schedule-*` で明示します。未来の `published_at` を設定するだけでは公開を待ちません。
- `.castloop/` は管理キーと操作記録を含みます。Gitへ追加せず、原本・設定とともに保全してください。キーの再発行機能はありません。
- 同じワークスペースや取り込みディレクトリを変更するCLIは、一度に1プロセスだけ実行します。実行中は入力ファイルを編集しません。
- 初期化や配備でR2を直接公開する必要はありません。非公開の試験では、素材のアップロード前に[全コンテンツ経路の保護](../design/security.md#非公開の実機試験)を確認します。
- 公開済み音源と履歴は通常更新で保持します。物理削除や未参照素材の自動削除は提供しません。
