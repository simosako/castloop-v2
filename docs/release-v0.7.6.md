# castloop v0.7.6

This release adds optional builtin Show websites (Issue #70), server-side scheduled publication (Issue #65) and offline encrypted workspace backup, verification and restore (Issue #63).

## Changes

- **Builtin Show websites (Issue #70).** `create-show ID --site-mode builtin` pre-generates a Show website in the Show Durable Object: newest-first 20-Episode listings, automatically shortened Episode page URLs, inline browser-native audio players, one default design, optional single-file Show CSS, plain-text excerpts and full descriptions with safe HTTP(S) links, and no copyright footer. Optional `site_timezone` in Show TOML controls website publication-date display only; RSS dates and Episode identities are unchanged. HTML is stored in private R2 and served through a separate HTML gateway/CDN entrypoint. External websites remain supported.
- **Scheduled publication (Issue #65).** Staged Show/Episode drafts can be frozen into a future UTC schedule outside the FIFO. `preview-episode-schedule`/`preview-show-schedule` return a hash to approve; `schedule-episode`/`schedule-show` create the schedule, and `schedule-list`, `schedule-status`, `schedule-reschedule`, `schedule-cancel` and `schedule-reapprove` observe or change it. Due schedules dispatch atomically through the existing Show Alarm. Pause, admission stop, maintenance and changed bases move due schedules to `needs_approval` for explicit reapproval.
- **Future `published_at` guard (Issue #65).** A future `published_at` is not a schedule. `preview-episode` reports `warnings[].code=future_published_at`; non-interactive `publish-episode` requires `--allow-future-published-at`, interactive runs ask to type `publish now`, and `publish-rss-import` requires the flag when any imported Episode is future-dated. Frozen jobs remain observable without the flag.
- **Workspace backup and restore (Issue #63).** `backup-create` writes one encrypted archive (scrypt + AES-256-GCM) with single-pass hashing, an explicit `--include-audio` opt-in for MP3 originals and a manifest recording every exclusion, retained lock, unfinished operation and frozen source path. `backup-verify` fully decrypts with per-entry digests and config validation; `backup-restore-preview` shows the restoration plan; `backup-restore ... confirm` restores into a nonexistent destination only, with the same service identity and partial-destination discard on failure. All four commands never network and never mutate the deployed service.

See the [website guide](show_website.md), [administrator configuration guide](admin_configuration.md), [backup guide](workspace_backup.md) and [observability guide](observability.md).

## Compatibility and safety

- **Fresh services only:** internal queue/content formats **11/11** and `website="static-show-v2"` are required. Service configuration remains schema 2 / `sqlite-sequential-v1` / `storage_layout="show-v1"`; Show/Episode metadata remains schema version 1. Earlier released v0.7.5 (7/8) services and former trial environments (8/9, 9/9, 9/10, 10/11) are not migrated, upgraded or adopted. Installing this CLI does not make an old service compatible; do not redeploy it onto an incompatible service.
- Publication remains explicit. Creating, scheduling, staging or uploading never publishes; due schedules and immediate publications still pass the lifecycle/readiness gates, and required Feed/cover/site cache purges must succeed before a publication commits. Immutable published audio, revision history and saved GUID/date/audio identities remain preserved.
- Backup commands are offline by design; restore refuses an existing destination and never continues a partially applied restore.
- Release and installation do not deploy, resume, publish to or change any Cloudflare resource.

## Verification and limitations

- The local reference suite passed **857 tests across 96 files**, TypeScript checks, the Linux standalone build and empty-PATH offline smoke checks. The tag release workflow repeats the Linux check/test suite and native build/smoke jobs on Linux x64, macOS Apple Silicon and Windows x64 before publication.
- Live verification was reviewer-only on private environments: a fresh isolated 9/9 environment published scheduled Episodes only after their due times and passed Pause/reapproval, reschedule/cancel, a far-future schedule coexisting with immediate publication and pre-due link denial; the private 11/11 environment verified three scheduled publications, one cancellation, Pause/reapproval, builtin site/feed updates and Cloudflare Access denial for all content paths. The reviewer separately confirmed website playback, full descriptions, short URLs, links, footer removal and Tokyo date display in the 10/11 trial. See the [9/9 live verification](../design/issue65_scheduled_publication_live_20261026.md), [11/11 private verification](../design/issue65_scheduled_publication_11_live_20261027.md), [adopted design](../design/episode_scheduled_publication_plan.md) and [backup plan](../design/workspace_backup_restore_plan.md).
- Not verified: Alarm redelivery, blocked-job interactions, same-time schedules, native Cloudflare CPU/Free-plan compatibility, mobile/keyboard browser acceptance of the combined website version, and backup restore against every real workspace shape. macOS/Windows checks do not establish full publication, concurrency or filesystem-safety behavior on those platforms. See the [binary distribution scope](cli_binary_distribution.md).
