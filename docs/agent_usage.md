# Managing a podcast with an agent

To ask an AI agent to operate castloop, install the Skill containing its management instructions. Then tell the agent which show to work on and what to do, review the preview, and instruct it to publish.

## 1. Install the Skill

Export the castloop Skill to your agent's Skill directory. This example places it in the project's `.agents/skills/` directory:

```sh
castloop skill export castloop --output /path/to/project/.agents/skills/castloop
```

Choose a new folder for the output. Follow your agent's instructions for where to store Skills and how to load them.

After updating the CLI, export the new Skill to a separate folder, review it, and replace the old one.

## 2. Describe the task

Give the agent:

- The workspace location
- The show and episode IDs
- What to create or change, and the audio or images to use
- The operations it is authorized to perform

For example, to prepare a change for review:

> Use the castloop Skill. The workspace is `/path/to/workspace` and the show is `my-show`. Update the description of episode `first` with the attached text and show me a preview before publishing. I will tell you when to publish after reviewing it.

Set up credentials using [environment variables](getting_started.md#1-set-cloudflare-credentials), and treat API tokens and administrator keys as secrets.

## 3. Review the preview and publish

Check the target, changes, audio, and cover. If you request edits, review the new preview afterward.

When requesting publication, specify the content and target you reviewed. The agent uses the preview hash to [publish](publishing.md). For scheduled publication, also check the time using the [scheduling guide](scheduling.md).

After publication, check the result and the show website.

If you also ask the agent to update the server or change a custom domain, specify each operation and its target clearly.

## Commands for agents

The CLI provides command syntax and input schemas:

| Information | Example command |
| --- | --- |
| Command arguments and behavior | `castloop describe publish-episode --json` |
| Show input fields | `castloop schema show-input` |
| Episode input fields | `castloop schema episode-input` |
| Example input | `castloop template show` |
| Validate show metadata and assets | `castloop validate show /path/to/workspace/my-show/show.toml --assets --json` |
| Validate episode metadata and audio | `castloop validate episode /path/to/workspace/my-show/episode-first.toml --audio /path/to/audio.mp3 --json` |

When creating a show or episode, use the editable files generated by `create-show` and `create-episode`.

Add `--json` to obtain JSON output. Check publication using `changed` or `unchanged` and `revision_id`, and check scheduled publication using `schedule-status`.

If an operation is interrupted, follow the [relevant checks](troubleshooting.md#when-an-operation-is-interrupted) to determine its status and how to continue.
